# Таксономия ошибок LLM при решении инженерных задач (v1.0)

Документ задаёт, **как размечать каждый неверный ответ модели**. Цель — чтобы два разметчика независимо ставили один и тот же код (проверяем каппой Коэна, см. §5).

## 1. Принцип: причина + симптом

Каждый неверный ответ получает:

1. **Один основной код** — *первопричину* (самую раннюю ошибку в цепочке рассуждений).
2. **Флаг `phys_flag`** — является ли итоговый ответ физически невозможным (true/false), независимо от причины.

Почему «физическая невозможность» вынесена во флаг, а не в отдельный код: невозможный ответ — это *симптом*, а не причина (к отрицательной температуре в Кельвинах может привести и ошибка знака, и неверная формула). Если сделать её отдельным кодом, разметчики будут расходиться, а статистика смешает причины. Флаг же отвечает на самостоятельный вопрос статьи: *замечает ли модель, что получила абсурд?*

## 2. Коды

| Код | Название | Определение | Примеры |
|---|---|---|---|
| `OK` | Верно | Все искомые величины в пределах допуска | — |
| `FORM` | Неверная модель / формула | Выбран не тот закон, неверная расчётная схема, граничные условия, пропущенное слагаемое, неверное допущение | M = qL²/2 вместо qL²/8; закон Ома для участка вместо полной цепи; адиабата вместо изотермы; ламинарная формула потерь при Re = 10⁵ |
| `DIM` | Размерность / единицы | Модель верна, но ошибка в переводе единиц, приставках, несогласованных единицах; ответ не в СИ | кН вместо Н (ошибка ×1000); литры не переведены в м³; °C вместо K в формуле газа; мм² вместо м² |
| `SIGN` | Знак / направление | Модель и единицы верны, ошибка в знаке или направлении | реакция вниз вместо вверх; работа над газом вместо работы газа; направление тока в контуре Кирхгофа |
| `ARITH` | Арифметика | Постановка и формулы верны, ошибка только в вычислении | 8.314·300 = 2394; ln 2 = 0.639; ошибка округления сверх допуска |
| `READ` | Неверное прочтение условия | Модель взяла не те данные или ответила не на тот вопрос | взяла R2 вместо R3; нашла давление вместо силы давления |
| `NOANS` | Нет ответа | Нет строки `FINAL_ANSWER`, отказ, обрыв по лимиту токенов, ответ не парсится | `stop_reason = max_tokens`; «недостаточно данных» при полных данных |

**Флаг `phys_flag = true`**, если итоговый ответ нарушает физический запрет. Ориентиры:
- механика: отрицательная масса/длина, коэффициент трения > ~1.5 без оснований, напряжение во много раз выше предела прочности любого материала при «бытовой» нагрузке;
- электротехника: отрицательное сопротивление пассивного элемента, КПД > 1, ток через идеальный разрыв, мощность нагрузки больше мощности источника;
- тепло/гидро: T < 0 K, КПД > 1 или выше КПД Карно, абсолютное давление < 0, теплота от холодного к горячему без работы, скорость выше скорости звука в несжимаемой модели.

## 3. Алгоритм выбора кода (в этом порядке)

```
Есть разборный ответ?                      нет → NOANS
Данные/вопрос прочитаны верно?             нет → READ
Физическая модель и формулы верны?         нет → FORM
Единицы и перевод в СИ верны?              нет → DIM
Знаки и направления верны?                 нет → SIGN
Иначе                                          → ARITH
```

Если в решении несколько ошибок — ставим **первую по этому порядку**. Если две ошибки компенсировали друг друга и ответ верен — `OK` (дополнительно можно отметить в `notes`).

Задача с несколькими искомыми величинами: код ставится по **первой неверной** величине в порядке `answers`.

## 4. Автоматические подсказки

Скрипт сравнения (`bench/answer.py`) пишет в `checks[].hint` подсказки — **это не разметка**, а помощь разметчику:
- `SIGN` — ответ совпадает с эталоном по модулю, знак противоположный;
- `DIM` — ответ отличается в 10ⁿ раз (n ≠ 0), типичный признак ошибки приставки;
- `MISSING` — величина не найдена в `FINAL_ANSWER`.

Подсказка `DIM` может оказаться и `FORM`, поэтому решение всегда за человеком после чтения решения модели.

## 5. Процедура разметки

1. Размечаются только записи с `correct = false` (верные проверяются выборочно, 10 %).
2. Поля в `runs/*.jsonl`: `error_code`, `phys_flag`, `annotator`, при необходимости `notes`.
3. **20 % неверных ответов размечаются двумя людьми независимо**, считается каппа Коэна по `error_code`. Цель — κ ≥ 0.7; при κ < 0.6 обсуждаем расхождения и уточняем этот документ (версия +0.1).
4. Разметчик не видит, какая модель дала ответ (поле `model` скрывается при экспорте на разметку) — снижает предвзятость.

## 6. Что анализируем в статье

- Доля каждого кода по моделям × домены × вариантам промпта.
- Снижает ли `guarded`-промпт долю `DIM` и `SIGN` относительно `zero_shot` (тест Мак-Немара на парных задачах).
- Доля `phys_flag = true` среди неверных ответов: насколько часто модель не замечает абсурдный результат и меняется ли это при `guarded`.
